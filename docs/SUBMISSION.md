# Submission and reproduction map

## Required repository files

| Assignment deliverable | Location | Behavior |
|---|---|---|
| Custom PySpark/Arrow components | `custom_transformers.py` | Haversine pandas UDF; persisted IQR and target encoding Estimator/Model pairs; batch history utilities |
| Ingestion → tuning → MLflow | `mllib_pipeline.py` | Root training entry point; shared implementation in `scripts/train_tournament.py` |
| Streaming inference | `inference.py` | Loads the complete model, derives raw JSON schema and runs `spark.readStream` |
| Metrics and importance plotting | `benchmark_results.py` | Root script evaluates labeled data and plots actual PCA variance/tree component importance |
| Mathematical/benchmark report | `docs/REPORT.md` | Mathematical derivations; historical numerical results explicitly identified |
| Serialized model | `models/<task>_full_pipeline/` or MLflow artifact | Generated by training; supplied separately from Git source |
| Production runner | `submit_pipeline.sh` | Fresh-process streaming microbatch with explicit model selection |

## Pipeline and tuning

The default raw-input pipeline persists eligibility, hour derivation, fitted
IQR bounds, imputation, categorical indexing/OHE, assembly, sparse-safe scaling,
PCA and estimator stages together. Each CV fit learns preprocessing only from
its training fold. Target encoding is available as a fitted component; the
baseline uses the required categorical indexing/OHE instead of target means.
Optional Arrow/history feature examples are in `notebooks/custom_transformers.ipynb`.

Five algorithm families are available across their appropriate task types:
ElasticNet LR and Gamma/log GLM for regression; LinearSVC for classification;
RF and GBT for both. Defaults use five-fold CV and parallelism 4. All candidates
within a task reuse the same 80/20 split and fold seed. Hyperparameter grids
include tree depth/maxBins and linear regularization. Gamma/log uses a fixed
positive-response offset with an inverse transform persisted in the pipeline.

The winner is chosen by CV, not held-out metrics. MLflow logs measured
parameters, CV/test metrics, PCA variance, tree component importance, diagnostic
artifacts and the full model. Staging/Production tags and registry aliases are
assigned only after fitting/evaluation. Data/model directories are not deleted
or overwritten by the normal workflow.

## Repository boundaries

Required executable submission files reside at repository root. Data
preparation, batch-only feature construction, training implementation and
legacy validation helpers reside in `scripts/`; tests reside in `tests/`.
`scripts/build_modeling_dataset.py` accepts explicit input/output paths and
preserves existing datasets. Optional notebook examples use synthetic data
and contain no saved execution state.

Historical evidence is separate from runtime inputs and new results. The
current training and benchmark commands generate measured diagnostics under
an explicitly chosen results directory.

## Validation limits

Small synthetic integration runs verify training/CV, save/load, actual metric
extraction, MLflow registration and fresh-process streaming. They do not
establish full-dataset accuracy or reproduce historical benchmark numbers.
A final submission must run the default tournament on the actual dataset and
include its resulting model artifact and measured report. Existing local model
directories and the Git placeholder alone do not establish this requirement.
